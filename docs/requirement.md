# 프론트엔드 채용 과제 요구사항

> 문서 유형: **Reference** — 구현 중 지켜야 할 계약과 제출 조건을 정의합니다.

## 과제 목적

이 과제는 다음을 확인하기 위한 과제입니다.

- 불완전한 요구사항을 해석하고 합리적으로 결정하는 방식
- AI를 포함한 도구를 목적에 맞게 사용하고 결과를 검증하는 방식
- 읽기 쉽고 변경하기 쉬운 코드를 만드는 개인의 코딩 스타일

## 기술 조건

- React 18 또는 19와 TypeScript를 사용합니다.
- 그 외 라이브러리와 프로젝트 구조는 자유롭게 선택합니다.
- 선택한 라이브러리와 구조가 문제에 적합한지는 평가 대상입니다.
- 색상은 CSS 변수, 테마 객체 등 일관된 토큰으로 관리합니다.
- 폰트는 Pretendard를 사용합니다.
- 아이콘은 기능을 구분할 수 있게 사용하며 심미성은 평가하지 않습니다.
- API는 별도 서버, 함수 수준 mock, MSW 등 익숙한 방식으로 구현할 수 있습니다. 실제 API로 교체할 때 코드 변경이 최소화되는지를 평가합니다.

## AI 활용

AI 도구 사용은 허용하며 사용 여부 자체로 가점이나 감점을 주지 않습니다. 평가 대상은 **사용 방식과 검증 과정**입니다.

AI를 사용했는지와 관계없이 루트에 `AI_USAGE.md`를 제출합니다. 작성 방법과 양식은 [AI 활용 기록 가이드](./ai_usage_guide.md)를 참고하세요.

- AI를 사용한 경우: 맡긴 작업, 채택하거나 거절한 제안, 사람이 검증한 방법을 기록합니다.
- AI를 사용하지 않은 경우: 사용하지 않았다고 밝히고 그 이유를 간단히 기록합니다.
- 전체 대화 원문 제출은 필수가 아닙니다.
- API 키, 개인 정보, 회사 정보 등 비밀정보는 포함하지 않습니다.
- 기록의 분량이나 사용한 도구의 브랜드보다 판단의 구체성과 검증 근거를 평가합니다.

## 공통 사용자 여정

### 내비게이션

- 대시보드(`/`): 대시보드 아이콘과 함께 표시합니다.
- 할 일(`/task`): 할 일 아이콘과 함께 표시합니다.
- 로그인 상태: 회원정보 아이콘을 표시하고 `/user`로 이동할 수 있어야 합니다.
- 비로그인 상태: 로그인 아이콘을 표시하고 `/sign-in`으로 이동할 수 있어야 합니다.
- 인증이 필요한 페이지에 비로그인 상태로 접근하면 로그인 후 원래 경로로 돌아갈 수 있어야 합니다.

### 대시보드 (`/`)

`GET /api/dashboard` 결과를 사용해 다음 값을 표시합니다.

| 항목 | API 필드 |
| :--- | :------- |
| 일 | `numOfTask` |
| 해야 할 일 | `numOfRestTask` |
| 한 일 | `numOfDoneTask` |

### 로그인 (`/sign-in`)

- 폼을 `POST /api/sign-in`으로 제출합니다.
- 성공이 아닌 응답에서는 `errorMessage`를 모달로 표시합니다.
- 모든 입력에 보이는 label을 제공합니다.
- 유효성 검증 실패를 해당 입력과 연결해 표시합니다.
- 이메일과 비밀번호가 모두 유효할 때만 제출 버튼을 활성화합니다.

| 입력 | 조건 |
| :--- | :--- |
| 이메일 | 필수값, 유효한 이메일 형식 |
| 비밀번호 | 필수값, 영문과 숫자로만 구성된 8~24자 문자열 |

### 할 일 목록 (`/task`)

- `GET /api/task` 결과를 카드 목록으로 표시합니다.
- 각 카드에 `title`과 `memo`를 표시합니다.
- 카드를 선택하면 `/task/:id`로 이동합니다.

### 할 일 상세 (`/task/:id`)

- `GET /api/task/:id` 결과를 표시합니다.
- 404 응답에는 목록으로 돌아가는 동작이 포함된 빈 상태 화면을 표시합니다.
- 삭제 버튼은 확인 모달을 엽니다.
- 확인 input에 현재 `id`를 정확히 입력한 경우에만 제출 버튼을 활성화합니다.
- 제출하면 `DELETE /api/task/:id`를 호출하고 성공 시 `/task`로 이동합니다.

### 회원정보 (`/user`)

`GET /api/user` 결과를 표시합니다.

## API 계약

[OpenAPI 문서](./openapi.yaml)를 API 경로, 요청, 응답의 기준으로 사용합니다. 요구사항과 OpenAPI 문서가 다르게 해석될 경우 README에 선택한 해석과 이유를 기록하세요.

## 제출물

프로젝트 루트에 다음 파일을 포함합니다.

- 실행 가능한 소스 코드
- `README.md`: 실행 방법, 구조, 주요 기술 선택, 검증 방법, 알려진 한계
- `AI_USAGE.md`: AI 활용 및 검증 기록

커밋 이력 제출이 가능한 환경이라면 작업 단위와 판단 흐름이 드러나는 커밋을 권장하지만, 커밋 수 자체는 평가하지 않습니다.
